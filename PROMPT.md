# Single generation prompt

Copy the prompt below into a coding assistant to generate the complete project.

```text
Build Crystal Cavern, a polished browser-playable C++17 puzzle adventure suitable
for a GitHub portfolio. Produce all working source, tests, documentation, and
GitHub Actions workflows. Keep one game-rules engine in C++, shared between a
terminal frontend and a WebAssembly browser frontend. Do not duplicate the rules
in JavaScript. Use Emscripten 4.0.15 to compile the browser engine.

The 15 x 9 level is:
###############
#@..#....*...E#
#.#.#.###.###.#
#.#.*...#...*.#
#.#.###.#.#.#.#
#...^...*.#...#
###.###.#.###.#
#*......+..^..#
###############

@ is the player, # a wall, . floor, * a crystal, ^ spikes, + a one-use potion,
and E the exit. Start with 5 health and 50 torch turns. Each successful move
spends a torch turn, while blocked moves and invalid inputs do not. Spikes remove
2 health on every visit, clamped at zero. Potions restore up to 3 health, capped
at 5, and are consumed even at full health. Collect all five crystals and enter
the exit to win. Zero health loses. An unlocked exit reached on the last turn
wins; otherwise zero torch loses. Freeze gameplay after a result. Escape score
is remaining torch times 10 plus health times 20. Restart restores everything.

Build an elegant dark, moss-green interface with pale lime accents, warm torch
light, readable typography, and the headline "A little light. A long way out."
The game should feel like a small finished indie project, not a dashboard demo.
Draw original stone walls, floor tiles, moss, crystals, a pixel explorer, spikes,
a potion, and a portal in Canvas 2D. Animate torchlight, crystal bobbing, movement,
particles, and a nudge into the wall when a move is blocked. Do not fetch any
art, fonts, or runtime libraries. Use a separate renderer, cached terrain, and
requestAnimationFrame. Size the drawing buffer to the display and its pixel
density, pre-render light and shadow sprites so frames stay cheap, copy the
cached terrain in device space as an unscaled one-to-one blit so it doubles as
the frame erase, and with reduced motion repaint only when the game state
changes because the scene is static.

Write the interface copy in plain sentences that say what the player does and
what it costs. Avoid taglines, paired fragments ("Small things. Big difference."),
three-item flourishes, and em dashes. Keep the single mood line "A little light.
A long way out." as the headline.

Offer immediate arrow-key and WASD movement without Enter, a mobile touch D-pad
with hold repeat, and a mobile HUD that keeps essential stats beside the map.
Pace held keys with one 140 ms step gate, and serve deliberate taps on the next
frame so a player who presses faster than the gate never loses a move.
Include a start screen, expedition sidebar, helpful field notes, a how-to-play
modal, pause with Esc/P, H for help, R for restart with confirmation, result and
replay screens, optional synthesized Web Audio effects, and locally stored best
score and sound preference. Respect reduced motion, handle blocked localStorage
and failed audio gracefully, and prevent moves while dialogs are open. Provide
accessible button names, visible focus states, focus-managed dialogs, and text
status updates. Show a useful retry screen if WebAssembly fails to load.

Use vanilla HTML/CSS/JavaScript with no runtime dependencies, and a small C ABI
bridge into the C++ engine. Ship compiled engine.js and engine.wasm so playing
only needs a static server. Preserve a standard-library-only terminal frontend.
Make targets: all, run, test, test-js, web, serve (configurable PORT), package,
test-web, and clean. Include an in-game source ZIP download generated by a
Python script.

Add native tests for gameplay boundaries, Node tests for the input pacing layer
(including that rapid taps keep their order, are never discarded, outrank an
aged repeat, and are capped for a scripted flood), and Playwright browser tests
that drive the real WASM engine. Verify winning and losing runs, last-turn
victory, replay, pause, dialogs, persistence, mobile layout and input, touch-pad
wall bumps, a hearts-only loss from the touch pad, wall-bump
feedback, dialog open animations, a frozen board under reduced motion,
drawing-buffer density handling, blocked storage, source download, and loading
failure recovery. Avoid a fake JS engine.

Add GitHub CI for GCC, Clang, sanitizers, input tests, WebAssembly compilation,
and browser tests. Add a manual GitHub Pages deployment workflow that rebuilds from C++.
Write a portfolio README with a real screenshot, one-command local play,
controls, architecture, native and WASM build instructions, testing, deployment,
and a MIT license. Add this prompt as PROMPT.md. Inspect desktop and mobile
screenshots and run the tests before reporting completion. Do not invent a
repository URL or publish without a destination supplied by the user.
```
